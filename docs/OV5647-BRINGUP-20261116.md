# E850-96 OV5647 단일 프레임 Bring-up (2026-11-16)

> **상태:** 640×480 RAW10 실제 사진 1프레임 획득 및 PNG 복원 성공. V4L2 `flags=0x4000`, `bytesused=0` 미해결. 본 작업은 교수님 upstream에서 제공한 OV5647 DTSI 및 Pablo bypass 코드를 적용·검증한 것이다.

## 1. 시스템 구성

- Board: E850-96 / Exynos 850, Linux 5.10.157 (ARM64, BusyBox initramfs)
- Sensor: OV5647, I²C Bus 7, 주소 0x36, Chip ID `0x5647`
- Driver: `fimc-is.ko`, `is-cis-ov5647.ko`
- Capture: `/dev/video102` (SS1 leader), `/dev/video214` (VC0 DMA)
- Host: WSL Ubuntu, Windows PowerShell, USB CDC-ACM COM5 (115200)
- Kernel source/build: `~/e850-kernel-src`, `~/e850-kernel-out-merged`

## 2. 적용 내용

1. 교수님이 제공한 `s5e3830-e850-ov5647-camera.dtsi`를 사용해 기존 S5KRC1S 카메라 설정에서 OV5647 기준으로 변경: 센서 ID/I²C/CSI 경로, LDO32 3.3V 전원, GPIO 및 전원 시퀀스 설정.
2. 교수님 `modules/ov5647-pablo/bypass.sh`로 3AA/ISP Chain이 없는 RAW-to-memory 경로를 설정: Sensor Group의 센서 참조 및 head/tail, CSIS Frame Start의 ISP 참조 회피, VC0 DMA Subdevice/Leader 처리, Sensor Frame End에서 Leader 자원 반환, LINE IRQ의 VC0 태깅 보완.
3. 커널과 `fimc-is`, `is-cis-ov5647` 모듈 재빌드. 오래된 외부 OV5647 모듈이 중복 패키징되지 않도록 제외한 다음 `tools/linux510/build-bootimg.sh`로 `boot.img` 구성 및 Fastboot로 플래시.
4. 보드에서 `modprobe fimc-is; modprobe is-cis-ov5647` 실행 후 OV5647 CIS 바인딩과 V4L2 노드를 확인.

사용한 Linux `boot.img` SHA-256: `54621fd3bc1267e0bfef365125df80fec59c23c281d1ef143e18cd7b7ba875ab`

## 3. 보드 캡처 명령

BusyBox에 Python3가 없어 Docker ARM64 Ubuntu 기반 Python 3.10 실행 환경을 만들어 COM5로 `/tmp/pyarm`에 전달하고, `ov5647-cap.py`를 `/tmp/ov5647-cap.py`에 준비.

```sh
PYTHONHOME=/tmp/pyarm/usr \
/tmp/pyarm/lib/ld-linux-aarch64.so.1 \
--library-path /tmp/pyarm/lib/aarch64-linux-gnu:/tmp/pyarm/usr/lib/aarch64-linux-gnu \
/tmp/pyarm/usr/bin/python3.10 \
/tmp/ov5647-cap.py -W 640 -H 480 -n 5 -t 5 -o /tmp/ov5647_scene
```

- 생성 RAW 파일: `/tmp/ov5647_scene_4.raw` = 750 KiB (DMA buffer 전체).
- 실제 픽셀 데이터: 앞 `640 × 480 × 2 = 614,400 bytes`, little-endian 16-bit/sample.
- 프레임 값: Min=30, Max=1023, 1%/99% 분위값 70/1023.
- 첫 테스트의 3개 연속 프레임 평균: 1.74 → 49.16 → 271.00. 노출/게인 변화 가능성은 있으나 확인되지 않음.

## 4. RAW → PGM → PNG 및 COM5 전송

1. Python `array('H')`로 RAW 선두 614,400바이트를 읽고, 1~99% 분위 범위로 대비 정규화해 `P5` 형식 640×480 흑백 `/tmp/ov5647_scene.pgm` 생성 (~300 KiB).
2. `gzip -c /tmp/ov5647_scene.pgm > /tmp/ov5647_scene.pgm.gz` 실행. 232,521 B, SHA-256 `f6ecd19175b1017b9bd482cc586c9ea48aa684608dd3c977873aa3281a7d8b49`.
3. 첫 COM5 바이너리 수신에서는 tty echo가 명령문 일부를 파일 앞에 기록해 GZip 헤더 오류 발생. 별도로 `stty -echo -opost` 전송 후 수신 버퍼를 비우고 고유 마커 `START_OV5647_DATA_2026` 뒤에서 정확히 232,521 B 수신하도록 수정; SHA-256 일치 확인.
4. Windows PowerShell `GzipStream`으로 PGM 압축 해제 후 `System.Drawing.Bitmap`으로 `C:\Users\DESKTOP\ov5647_scene.png` 생성. 인형·책상·케이블 등 실제 장면 식별 성공.

## 5. 남은 문제 및 다음 목표

- **모든 VC0 버퍼에서** `flags=0x4000` (`V4L2_BUF_FLAG_ERROR`), `bytesused=0` 반복: 실제 이미지 수신은 확인됐지만 정상 V4L2 Frame Completion 미확인.
- `e850_csi_crc_count`는 5프레임 캡처 전후 `0 → 0`. CRC 이외 CSI 오류 또는 Pablo Bypass의 buffer completion 문제는 배제되지 않음.
- 다음: `is-device-csi_v4.c`의 `csi_dma_tag()`, CSI 에러 처리 및 V4L2 buffer completion 경로 분석 → 오류 없는 연속 프레임 및 FPS 검증 → HDMI 정지 영상 출력 → 실시간 HDMI 출력.
