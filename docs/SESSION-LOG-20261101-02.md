# 작업 대화 기록: 2026-11-01 ~ 11-02 (Claude Code 세션)

E850-96 Linux 5.10 + Debian 12 bring-up 세션에서 사용자와 나눈 대화와 결정, 결과를 시간순으로 정리했다. 기술 세부는 [E85096-LINUX510-BOOT.md](E85096-LINUX510-BOOT.md) 11장에 있고, 여기서는 그 절을 가리킨다. 원본 대화 기록(JSONL)은 Mac의 `~/.claude/projects/`에 있고, `~/claude-transcript-backup/`에 5분마다 복사된다.

## 1. 세션 복구와 작업 환경

| 시각(KST) | 사용자 요청 | 한 일 / 결과 |
|---|---|---|
| 11-01 | 인터넷이 끊겨 이전 세션이 죽음. 할 일, 체크리스트, 깃 주소 요청 | 이전 세션의 `/tmp` 작업 폴더가 지워져 커밋 안 된 수정이 사라졌다. 대화 기록(JSONL)에서 수정 내용을 되살려 `~/e85096-dvs-bringup`에 다시 적용하고 push했다 |
| 11-01 | 디버거만 꽂으면 Mac 인터넷이 끊김 | 보드의 DHCP가 Mac에 기본 게이트웨이를 내주고 있었다. `EmitRouter=no`로 고치고(11.5), 사용자가 Mac 네트워크 서비스 순서를 Wi-Fi 우선으로 바꿨다 |
| 11-01 | "기록하면서 하고, 토큰 다 쓰면 충전되면 자동으로 이어서 해" | 매시 17분 자동 재개 점검(cron, 세션 안에서만 동작)을 걸었다. 단계마다 문서에 적고 커밋·push한다 |

## 2. 8코어와 안정성

| 내용 | 결과 | 문서 |
|---|---|---|
| MCT 타이머 때문에 CPU1이 lockup | `exynos_mct`를 빼고 arch timer를 사용 | 11.3 |
| CPU2~7이 켜지지 않음 | DT의 CPU `reg`를 이 보드 BL31 방식(`cluster<<8 \| core`)으로 바꿈. **8코어 동작** | 11.6~11.8 |
| 1시간 8코어 부하 시험 | 통과. 오류 0, 최고 87℃(방열판 권장) | 11.11 |
| CPU hotplug(끄고 다시 켜기) | Linaro mainline 패치와 비교해 PMU 쓰기 두 가지를 넣은 `e850-cpuhp` 모듈로 해결. 30회 + 무작위 300회, 실패 0 | 11.9, 11.13 |
| `cpuidle.off=1` 빼기(C2 idle) | C2에 들어간 코어가 깨어나지 않음. Linaro v7 소개글도 "올바른 펌웨어가 필요"하다고 적음. **펌웨어 문제로 보고 보류**, `cpuidle.off=1` 유지 | 11.12, [C2 참고 메모](E85096-C2-CPUIDLE-REFERENCE-20261102.md) |

C2 시험 중 보드가 두 번 멈췄다. 한 번은 사용자가 전원을 껐다 켰고, 한 번은 워치독 리셋 뒤 fastboot에서 자동으로 원래 이미지로 복구했다.

## 3. 카메라와 화면

| 내용 | 결과 | 문서 |
|---|---|---|
| 실시간 영상이 12~16 fps | 처음에는 CPU 병목으로 판단했지만 틀렸다. 원인은 센서 VTS가 리셋값이었던 것(초당 약 16장)과, 프레임마다 나오는 커널 메시지가 115200 baud UART로 나가던 것 | 11.10 |
| 해결 | 드라이버가 모드별 VTS를 쓰게 하고, 캡처하는 동안만 콘솔 로그를 끔. **55~63 fps**. 화면 그리기도 2배 빠르게 고침 | 11.10 |
| HDMI 글자가 파란색 → 흰색으로 | fb가 흑백(MONO01)으로 보고되고, DECON이 팔레트 쓰기를 버리던 문제. `e850-fbpal` 모듈과 `e850-hdmi.service` 수정으로 **흰 글씨**. 재부팅 후에도 유지 | 11.14 |

## 4. 사용자 질문과 답

- **보드가 리셋되나?** 자동 재개 점검은 보드를 리셋하지 않는다. 보드가 멈출 수 있는 시험은 사용자가 있을 때 진행했다.
- **VS Code에서 하면 대화가 남나?** Claude Code 대화는 어디서 하든 `~/.claude/projects/`에 남는다. 위 1절처럼 보존 기간을 늘리고 백업했다.
- **데스크톱은 언제 올리기로 했나?** 저장소와 남은 대화에서 그런 기록을 찾지 못했다. 지금은 올리지 않기로 했다. GPU용 사용자 공간 드라이버가 없어 화면을 CPU로 그려야 하고, USB 호스트(키보드·마우스)가 꺼져 있으며, YOLO 영상 처리에는 framebuffer 직접 출력이 더 낫다.
- **adb가 계속 연결돼 있어야 하나? Wi-Fi로 ssh 되나?** adb는 쓰지 않는다. 평소 작업은 Wi-Fi ssh(`philip@192.168.0.236`)로 충분하다. 보드가 멈출 수 있는 시험 중에는 USB(fastboot 복구, 시리얼 콘솔)와 UART(커널 로그)를 꽂아 둔다.
- **GitHub에 계속 올리나?** 단계마다 커밋하고 push한다.

## 5. 앞으로 할 일 (사용자 계획)

1. **MySQL + Apache로 사람 출입 기록**: 시스템 안정화는 끝났다. 정할 것이 하나 남았다. nginx가 이미 80번 포트를 쓰므로, nginx를 끄고 Apache로 바꿀지 Apache를 다른 포트(예: 8080)로 띄울지 사용자가 정한다.
2. **YOLO nano 영상 처리**: ncnn 또는 ONNX Runtime(8코어 CPU)을 쓴다. 카메라 → 추론 → 박스 그리기 → HDMI framebuffer 순서로 연결한다. 모델 종류(YOLOv8n/YOLO11n 등)는 확인이 필요하다.
3. 보류: C2 idle(펌웨어), 데스크톱(필요해지면 USB 호스트부터 살림).
